## Highlights

- **Repository workspace** — stage and unstage files, commit and amend, inspect history and diffs, manage remotes, tags, stashes, Git LFS, and multiple repositories.
- **Safer branch switching** — move, stash, or explicitly discard working-copy changes; ignored paths and unsafe nested repositories are protected.
- **Merge and rebase workflows** — preview operations, resolve conflicts, edit rebase plans, use autosquash, and recover interrupted Git jobs.
- **Worktrees and submodules** — background loading, metadata watching, management actions, and linked-worktree awareness.
- **GitHub pull requests** — create and review PRs, inspect checks and timelines, comment on diffs, manage labels and reviewers, and open the PR for an exact branch or fork.
- **Background operations** — cancellable fetch, pull, push, clone, merge, rebase, submodule, and worktree jobs with streamed command logs.
- **Terminal launcher** — open a repository with `giteye .`; later launches reuse and focus the running app.
- **Build diagnostics** — Settings → About reports the running version, compiled source commit, application ID, runtime, platform, and Git toolchain details.

## Install

Download the latest build from [GitHub Releases](https://github.com/alfkonee/giteye/releases/latest):

| Platform | Packages |
|---|---|
| Linux x64 | AppImage, Debian (`.deb`), RPM |
| Windows x64 | NSIS (`.exe`), MSI |
| macOS Apple Silicon | DMG, app archive |
| macOS Intel | DMG, app archive |

Published builds use the application identifier `com.giteye.app`. Release artifacts are generated by [the release workflow](.github/workflows/release.yml), and their versions are checked against the release tag.

### Terminal launcher

GitEye can install a user-scoped launcher from the first-run prompt or **Settings → General → Command-line launcher**. Installation does not require administrator access and never edits `PATH` or shell profiles automatically.

```sh
giteye .
giteye /path/to/repository
giteye "/path/with spaces/repository"
giteye -- -repository
giteye --help
giteye --version
```

Nested directories resolve to their Git root; linked worktrees open as separate workspaces. To manage the launcher directly:

```sh
/path/to/giteye --install-cli
/path/to/giteye --uninstall-cli
/path/to/giteye --install-cli --install-dir "$HOME/bin"
```

The default launcher location is `~/.local/bin/giteye` on Linux/macOS and `%LOCALAPPDATA%\GitEye\bin\giteye.cmd` on Windows. Move the application to its permanent location before installing the launcher.

## Requirements

For normal use:

- Git
- [GitHub CLI (`gh`)](https://cli.github.com/) authenticated for GitHub collaboration features
- Git LFS is optional

For development:

- [Bun](https://bun.sh/) 1.x or later
- Stable [Rust](https://www.rust-lang.org/tools/install)
- [Tauri 2 system dependencies](https://v2.tauri.app/start/prerequisites/) for your platform
- Git

## Development

```sh
git clone https://github.com/alfkonee/giteye.git
cd giteye
bun install --frozen-lockfile
bun run tauri
```

The development command starts Vite on an available local port and launches the Tauri application. GitEye is single-instance: later launches forward repository paths to the existing process.

### Checks

Run the same core checks used by CI:

```sh
bun run test
bun run build
cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
```

Seed disposable repositories for manual testing:

```sh
bun run qa:seed
```

See [docs/manual-qa.md](docs/manual-qa.md) for the manual verification matrix.

### Desktop builds

```sh
bun run tauri:build       # platform desktop bundle
bun run build:appimage    # Linux AppImage
```

CI stamps the checked-out source commit into the native binary. Release builds synchronize the version from the release tag, then require matching versions in `package.json`, Tauri configuration, `Cargo.toml`, and `Cargo.lock`. Builds also enforce the canonical `com.giteye.app` identifier. Settings → About displays the resulting runtime metadata.

## Architecture

GitEye uses a React/TypeScript frontend inside Tauri 2, backed by Rust services for Git, filesystem, credential, and provider operations.

```text
src/
├── app/             Application providers and shell
├── components/      Workspace, history, review, settings, and shared UI
├── hooks/           Query and workflow hooks
├── lib/             Tauri API, query definitions, watchers, utilities
├── stores/          Local UI and job state
└── types/           Frontend contracts

src-tauri/src/
├── commands/        Tauri command boundary
├── git/             Git, GitHub, toolchain, and job services
├── models/          Serialized frontend/backend contracts
├── storage.rs       Persistent application state
├── watcher.rs       Repository metadata watching
└── lib.rs           Application and plugin wiring
```

Blocking subprocess, network, filesystem, and keychain work is kept off the Tauri UI thread. Long-running repository mutations use a background job runner with per-repository serialization, cancellation, recovery, and streamed logs.

See [docs/architecture/library-decisions.md](docs/architecture/library-decisions.md) for dependency and rendering decisions.
